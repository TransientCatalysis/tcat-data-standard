# What is enforced, when, and why the split falls there

TRACE-AI is a **reporting** standard: it is designed to be filled in at publication. This project needs an **operational** data model: something that is true continuously, while data is being acquired at three institutions.

Those are different jobs, and conflating them produces one of two failures. Enforce everything on every commit, and the process becomes intolerable and gets routed around — at which point you have neither the process nor the honesty about not having it. Enforce nothing until manuscript time, and the fields that had to be captured at acquisition are already gone.

So the split is drawn on one question: **would this information be unrecoverable if not captured now?**

- **Unrecoverable → required schema field, enforced in CI on every PR.** A deleted failed run cannot be un-deleted. A batch grouping cannot be reconstructed from a spreadsheet six months later. An unstated unit is a guess forever.
- **Assembled at write-up → generated at write-up.** Metric tables, ablations, and campaign narratives are assembled from records that already exist. Requiring them per commit adds nothing and costs compliance.

---

## Enforced in CI (data items A1–A4)

Every PR to any spoke repository runs `tcat-validate`. Exit status 0 is the definition of ingestible.

| Item | Upstream text (abbreviated) | How it is enforced |
|---|---|---|
| **A1** | Describe semantic and numerical harmonization steps | `channels[].units` and `channels[].quantity` required per channel; UTC timestamps with explicit offset; harmonisation recorded as a provenance record with an artifact id, not as prose |
| **A2** | Provide processing code that regenerates the dataset; state how equivalence is checked | `provenance.tool` (name, version, git sha) required on every artifact; `files[].sha256` always, plus `rows` for CSV and `shape` for Zarr as the equivalence check |
| **A3** | Define all input features and their generation pipeline | `channels` required and non-empty, each with units, quantity, and uncertainty; generation is the provenance chain |
| **A4** | Provide dataset identifiers, access details, and core metadata sufficient for reuse | `dataset_id`, `instrument`, `sample_id`, `access_status`, `license`, `measurement_type` all required |

## Required schema fields, not CI-checkable as items (A5, B2)

These two are enforced structurally rather than as checklist assertions, because a checklist answer of "yes we retain failed runs" is not verifiable and a required field is.

| Item | Upstream text | How it becomes structural |
|---|---|---|
| **A5** | State policy on negative/failed/suboptimal experiments and include if informative | `status` ∈ {`ok`, `flagged`, `failed`} is **required**; `status_reason` is required and non-empty whenever status is not `ok`. **Flag, never delete.** Required in 0.1.0 rather than added later, because retrofitting it means the record of what failed is already gone. At manuscript time an exclusion table with counts is generated by query, not asserted. |
| **B2** | Describe data-split strategies implemented to prevent information leakage | `batch_id` and `lineage_id` are **required**. Catalysis data has shared lineages, repeated conditions, and time-series structure — each a leakage pathway. A validator cannot enforce grouped splits unless the grouping keys exist, and they cannot be reconstructed after the fact. Same-batch data must stay within a single split; the fields are what make that checkable. |

## Recorded, not enforced

| Item | Field | Why recorded and not enforced |
|---|---|---|
| **C2** (partial) | `autonomy_level` (A0–A5) | Recording costs one enum. Enforcing anything about it requires the campaign to be over. |

## Structural, via the `model` document (B1, B2, B3, B5)

Adding a `model` document kind moved four Model Development items from "assembled at write-up" to "recorded as you go". They are not CI-enforced as checklist items — a model is not required to exist — but when one does exist, the schema requires or warns about exactly what the checklist asks for. That is a better place for them than a report generator, because a metric's confidence interval has to be computed when the fit runs, not recalled months later.

| Item | Upstream text (abbreviated) | Where it now lives |
|---|---|---|
| **B1** | Document full model specification: architecture, hyperparameters, objective, versions | `model.architecture`, `model.hyperparameters`, `model.algorithm`, `model.software`, `model.seed` — all present, most required |
| **B2** | Describe data-split strategies implemented to prevent information leakage | `model.training_data.splits` — expressed as **groups** (`batch_id` / `lineage_id`), not rows, so `tcat-index`'s `check_index.py` can **fail** when a group appears in two splits. Row-level splits of autocorrelated PRBS data leak and look fine; group-level ones are checkable |
| **B3** | Metrics with confidence intervals, to avoid best-only reporting | `model.metrics.<name>` requires `split`; an absent `interval` produces a warning naming best-only reporting |
| **B5** | Describe the UQ method, its calibration and utilization | `model.uncertainty_ref` → an `uncertainty-ensemble` document carrying `method` and `method_family`, so an asymptotic approximation cannot be read as a sampled posterior |

**B4** (justify metric choice, examine multi-objective trade-offs) stays at manuscript time. It is an argument, not a field, and a schema that demanded one would get "see manuscript".

Also structural, from the DMSP rather than TRACE-AI, and useful for the same reason: `model.limitations` — limitations on appropriate use, warned about when empty. Upstream has no equivalent item, and it is a candidate for the profile we contribute back.

## Deferred to manuscript time (B4, C, D)

Generated by `tcat-analysis/report/trace_ai.py` — currently a stub — from accumulated records, at the point a manuscript is prepared. **Not a commit gate.**

| Section | Items | Source it will be generated from |
|---|---|---|
| **B** Model Development | B4 | The manuscript's own argument, cross-referenced against `model.metrics` and `model.objective` |
| **C** Workflow Integration | C1, C2, C3, C4, C5 | Agent run records and design-criterion provenance. Largely absent in Phase I, which is honest — the loop is human-gated at A1–A2 |
| **D** Executable Artifacts | D1, D2, D3 | `model.example_use` and notebooks in `tcat-analysis/examples/`, plus lockfiles and `provenance.environment` |

The `publication` document is what the generator runs over. It enumerates every artifact, dataset, sample, and model the paper rests on, with the role each plays — so "walk provenance backwards from every cited artifact" has a defined starting set rather than requiring a guess. Its `trace_ai_checklist.gaps` field is where unsubstantiated items are recorded **as gaps**.

The report generator's job is to fail loudly about what it *cannot* fill in, rather than to emit a plausible-looking checklist with gaps. A checklist that quietly reports "N-A" for an item nobody looked at is worse than an empty one.

## Deferred entirely

| Thing | Why |
|---|---|
| **Agent card** | The full card — observation space, action space, objectives, constraints, policy, tool access, safety checks, seeds — targets unattended closed loops. This project is A1–A2, human-gated. Deferred until something runs unattended, so it can be written against a real loop rather than an imagined one. |
| **Ontology / controlled-vocabulary alignment** | Aspirational even in the paper. Vocabulary emerges through `extensions` and is promoted once the same field appears independently in three labs (STANDARD.md §6). Choosing an ontology before knowing what the labs actually record produces a mapping nobody uses. |

## Manuscript-time checklist procedure

Not yet implemented; recorded here so the interface does not have to be retrofitted.

1. `tcat-report trace-ai --publication <publication_id>` reads the publication document and walks provenance backwards from every artifact it names. The publication document is what makes the starting set defined rather than guessed.
2. It fills the machine-readable checklist (`checklist/trace-ai-checklist.json` at the pinned version) with evidence pointers — artifact ids, not file paths.
3. Items it cannot substantiate are reported as **gaps with the reason**, never as satisfied and never silently as `N-A`.
4. Autonomy run logs, where any exist, are generated from agent run records against the upstream template.
5. Output goes into the SI alongside the pinned checklist version, cited per upstream's own guidance ("cite the version you used").
